# GF 插件更新协议

本文档规定编码 Agent 在消费项目中收到“更新 GF 插件”“升级 GF 插件”或明确同义请求时的操作流程。
更新对象固定为当前项目的 `addons/godot_framework`。更新请求只授权准备更新；真正写入前必须再次询问
用户是否同意无备份覆盖。任何确认都不授权修改、提交或推送消费项目的业务代码、场景、资源、项目配置
或根 `AGENTS.md`。

## 更新来源与默认目标

- 官方仓库固定为 `https://github.com/ZhaoMCX/godot-framework`，目标官方包的 `version.cfg` 中 `source`
  必须与其一致；已安装插件的来源缺失或不同不阻止用户确认覆盖。
- 当前版本尽量从 `addons/godot_framework/version.cfg` 的 `version` 读取；文件缺失或格式无效时显示为
  “未知”，但不因此阻止用户确认覆盖。
- 未指定目标版本时，查询官方仓库 GitHub Releases 的最新稳定版；忽略草稿和预发布版本。
- 发布标签固定为 `v<version>`，资产固定为 `godot-framework-<version>.zip` 和同名 `.sha256` 文件。
- 当前版本等于目标版本时仍执行确认和整目录重装，以恢复官方纯净内容。
- 当前版本高于默认目标版本时停止，不自动降级。只有用户明确指定较低版本时才允许降级；安装预发布
  版本也必须由用户明确指定。

## 更新准备与确认

任何替换操作前必须完成以下只读准备；准备失败时保持项目不变。

1. 将项目根目录和 `addons/godot_framework` 解析为绝对路径，确认目标目录位于当前项目内且路径完全匹配，
   且已经存在；不得对工作区根目录、`addons` 或其他宽泛目录执行删除或替换。缺少该目录时停止并报告
   需要首次安装，不把更新请求扩展为安装。
2. 尽量读取当前版本，只用于确认提示和降级判断。不检查插件 Git 工作区状态，不比较本地目录与任何
   旧版官方资产；本地新增、修改和删除都不会阻止更新，也不会被保留。
3. 按“下载与验证”完成目标官方包的全部校验并解压到操作系统临时目录，确认写入内容已经就绪。
4. 写入前向用户列出所有目标项目的绝对插件路径、当前版本和目标版本，并使用以下含义明确的提示询问：

   > 将把以下项目的 `addons/godot_framework` 整目录覆盖为官方 GF vX.Y.Z。现有目录及其中所有本地修改
   > 会被永久删除，不创建备份。是否继续？

批量更新可以一次确认全部明确列出的项目。用户拒绝或未明确同意时，删除下载暂存内容且不写入任何
项目；不得把最初的更新请求视为这一步确认。

## 下载与验证

所有下载和解压都在操作系统临时目录中完成，不得直接写入目标插件目录。

1. 获取目标 Release 元数据，确认标签、稳定版状态和资产名称符合约定；读取 Release Notes，记录其中的
   兼容性与迁移提示，但不得据此修改消费项目代码。
2. 下载目标 ZIP 与 `.sha256`，校验文件中必须只有目标 ZIP 的文件名和 SHA-256；实际哈希必须匹配。
3. 检查 ZIP 中的每个条目：不得使用绝对路径、`..` 路径穿越或链接跳出解压目录；所有发布文件必须
   位于唯一的 `addons/godot_framework` 根下。
4. 解压到临时暂存目录，确认至少包含 `AGENTS.md`、`LICENSE`、`README.md`、`version.cfg`、
   `docs/update.md` 和 `base/gf_application.gd`，且任何层级都不得包含 `tests` 目录。
5. 暂存包的 `version.cfg` 名称和官方来源必须正确，版本必须同时匹配 Release 标签和资产文件名。

任何网络、Release 元数据、哈希、归档结构或版本检查失败都必须在替换前结束，并删除已下载的临时内容。

## 无备份整目录替换

用户确认后才允许执行以下操作：

1. 再次确认目标绝对路径与确认提示中的路径完全一致。
2. 不检查、不复制也不备份旧插件目录，直接删除经过验证的 `addons/godot_framework`，只把暂存包中的
   同名完整目录复制回原位。
   禁止逐文件合并，因为新版本已删除或移动的旧文件会因此残留。
3. 比较安装目录与暂存官方包的文件清单和内容，必须完全一致；再次读取 `version.cfg`，确认版本、名称
   和来源与目标 Release 一致。
4. 不要提交、暂存或推送消费项目中的更新结果。

## 消费项目验证

1. 按消费项目根目录及目标路径的 `AGENTS.md` 执行已有验证命令。
2. 使用项目配置的 Godot 可执行文件进行无界面编辑器导入和脚本解析；没有专用命令时使用等价于
   `godot --headless --editor --path <项目根目录> --quit` 的检查。
3. 若消费项目定义了自动化测试，则运行其规定的受影响测试。验证期间不得通过修改消费项目代码来适配
   新版 GF；兼容问题只报告，不在本次更新范围内修复。

验证结束后删除下载暂存内容，并报告旧版本、新版本、Release URL、ZIP SHA-256 与验证结果。若替换、
Godot 导入、脚本解析或项目测试失败，保留当前文件状态并说明失败信息；由于更新不创建备份，不得自动
恢复旧版，也不得擅自修改消费项目代码。用户之后可以明确指定已发布的旧版本，按同一确认流程重新安装。
