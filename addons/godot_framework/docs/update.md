# GF 插件更新协议

本文档规定编码 Agent 在消费项目中收到“更新 GF 插件”“升级 GF 插件”或明确同义请求时的操作流程。
更新对象固定为当前项目的 `addons/godot_framework`。用户的更新请求已经授权替换该目录，但不授权修改
消费项目的业务代码、场景、资源、项目配置或根 `AGENTS.md`。

## 更新来源与默认目标

- 官方仓库固定为 `https://github.com/ZhaoMCX/godot-framework`，已安装插件的 `version.cfg` 中 `source`
  必须与其一致。
- 当前版本读取 `addons/godot_framework/version.cfg` 的 `version`。
- 未指定目标版本时，查询官方仓库 GitHub Releases 的最新稳定版；忽略草稿和预发布版本。
- 发布标签固定为 `v<version>`，资产固定为 `godot-framework-<version>.zip` 和同名 `.sha256` 文件。
- 当前版本等于目标版本时不修改文件，只报告已经是最新版本。当前版本高于目标版本时停止，不自动降级。
- 用户明确指定版本时，只接受官方仓库中已发布且非草稿的对应版本；安装预发布版本必须由用户明确要求。

## 更新前检查

任何替换操作前必须完成以下检查；检查失败时保持项目不变。

1. 将项目根目录和 `addons/godot_framework` 解析为绝对路径，确认目标目录位于当前项目内且路径完全匹配，
   不得对工作区根目录、`addons` 或其他宽泛目录执行删除或替换。
2. 读取并校验已安装的 `version.cfg`。版本、名称或官方来源缺失、格式无效或来源不匹配时停止。
3. 检查 `addons/godot_framework` 的 Git 工作区状态；存在未提交修改、新增或删除时停止并列出文件。
4. 下载当前已安装版本的官方 ZIP 和校验文件，验证 SHA-256 后，将其插件子树与本地目录比较。文件清单
   或内容不同即视为本地定制并停止；文本文件仅有 CRLF/LF 换行差异不视为修改。当前版本官方资产不可
   获取或无法验证时也停止，不以猜测覆盖现有插件。

## 下载与验证

所有下载和解压都在操作系统临时目录中完成，不得直接写入目标插件目录。

1. 获取目标 Release 元数据，确认标签、稳定版状态和资产名称符合约定；读取 Release Notes，记录其中的
   兼容性与迁移提示，但不得据此修改消费项目代码。
2. 下载目标 ZIP 与 `.sha256`，校验文件中必须只有目标 ZIP 的文件名和 SHA-256；实际哈希必须匹配。
3. 检查 ZIP 中的每个条目：不得使用绝对路径、`..` 路径穿越或链接跳出解压目录；所有发布文件必须
   位于唯一的 `addons/godot_framework` 根下。
4. 解压到临时暂存目录，确认至少包含 `AGENTS.md`、`LICENSE`、`README.md`、`version.cfg`、
   `docs/update.md` 和 `base/gf_application.gd`，且任何层级都不得包含 `tests` 目录。
5. 暂存包的 `version.cfg` 名称和官方来源必须正确，版本必须同时匹配 Release 标签和资产文件名。

任何网络、Release 元数据、哈希、归档结构或版本检查失败都必须在替换前结束，并删除已下载的临时内容。

## 整目录替换

1. 在操作系统临时目录创建旧插件的完整备份，并验证备份文件清单与源目录一致。
2. 删除经过绝对路径校验的 `addons/godot_framework` 目标目录，只把暂存包中的同名完整目录复制回原位。
   禁止逐文件合并，因为新版本已删除或移动的旧文件会因此残留。
3. 再次读取已安装的 `version.cfg`，确认版本、名称和来源与目标 Release 一致。
4. 替换和后续验证完成前保留旧版备份；不要提交、暂存或推送消费项目中的更新结果。

## 消费项目验证

1. 按消费项目根目录及目标路径的 `AGENTS.md` 执行已有验证命令。
2. 使用项目配置的 Godot 可执行文件进行无界面编辑器导入和脚本解析；没有专用命令时使用等价于
   `godot --headless --editor --path <项目根目录> --quit` 的检查。
3. 若消费项目定义了自动化测试，则运行其规定的受影响测试。验证期间不得通过修改消费项目代码来适配
   新版 GF；兼容问题只报告，不在本次更新范围内修复。

所有验证通过后删除旧版备份和下载暂存目录，并报告旧版本、新版本、Release URL、ZIP SHA-256 与验证
结果。若 Godot 导入、脚本解析或项目测试失败，则保留新版和旧版备份，说明失败信息并询问用户选择：

- 保留新版并自行处理兼容问题；或
- 恢复旧版并清理失败更新的临时内容。

得到选择前不得删除备份，也不得擅自修改消费项目代码。

## 首次接入

本协议从 `v0.1.1` 起随正式插件包发布。使用 `v0.1.0` 的项目需要先手动整目录替换到 `v0.1.1`；从
`v0.1.1` 开始，后续版本可按本协议响应一句话更新请求。已发布的旧版本 ZIP 和校验文件不得被替换。
